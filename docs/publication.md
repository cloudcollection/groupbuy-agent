# GitHub 发布检查

发布内容限定为 publication-files.json 所列代码、模板、说明、GPL 许可、虚构样例和测试。真实任务、HAR、缓存、采集结果、日志、截图、账号路径、认证材料、证书、VPN 设置都不在白名单。

```powershell
git init -b main
git config core.hooksPath .githooks
python -B -m unittest discover -s tests -v
python -B tools/prepare_index.py
python -B tools/release_check.py
git diff --cached --check
```

准备脚本仅按精确白名单暂存，不使用 `git add .`。提交前钩子执行扫描，但用户可以绕过钩子，因此发布检查不以钩子为唯一保障。扫描每个工作文件、每个暂存 blob 和所有可达历史 blob/提交元数据；发现凭据、手机号、个人目录或旧业务术语时失败。不打印匹配值。第三方安装目录 .venv 与字节码缓存不扫描，但无法进入白名单。

仅未暂存、无敏感匹配的本地文件会统计为 excluded；任何暂存或历史文件不在当前精确白名单都会失败。runtime 下的未暂存状态日志仍检查敏感内容，但不因扩展名阻塞本地使用。禁用类型如 HAR 即使未暂存也会使扫描失败，应在仓库外保管，再从配置引用；不要为了通过扫描删除用户输入。

扫描是规则检查，不能识别所有任意格式的秘密，也不能自动证明一份业务数据是虚构的。人工核对样例生成器、白名单变更、许可证和暂存差异仍然必要。不要将真实输入加入 examples，不能以“脱敏后”为由提交真实采集结果。

本版已准备独立本地 Git 仓库，使用通用作者身份创建初始提交；没有设置远端、没有读取 GitHub 认证、没有推送。只有用户明确指定推送后再连接目标仓库，推送前重新运行完整扫描。若误提交秘密，应修复历史并更换凭据，单独新增删除提交仍会被历史扫描拦截。
