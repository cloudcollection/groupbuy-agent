# 第一次使用独立 Agent

下载本仓库，在自己的 Windows 电脑运行。需要 Python 3.10+；UI 建议先使用 Python 3.11 或 3.12。运行 Agent 不需要 Codex、MCP 或共享账户。真实模型请求使用自己的 API Key，按所选服务商计费。

## 1. 安装与启动

把仓库放在 D 盘，在项目根目录打开 PowerShell：

```powershell
./setup.ps1 -WithUI
./.venv/Scripts/python.exe -B -m groupbuy doctor
./start-ui.ps1
```

浏览器打开 `http://127.0.0.1:8787`，终端保持运行。已有 `.venv` 会复用，安装脚本会显示其 Python 版本；不会用系统里另一个 Python 覆盖它。源码采用可编辑安装，CLI 与网页使用当前工程。首次创建环境可用 `-PythonExecutable` 指定已安装的解释器。所有安装临时目录和 pip 缓存设在 D 盘。

## 2. 先用离线演示

点击“体验离线演示”。无需 Key，也不联网请求模型或操作微信。脚本模拟模型选择工具，真实执行虚构数据的解析、质量检查和导出。结果写入独立目录，不能作为真实采集成功的证明。

## 3. 保存一项任务并校准页面

先填一行虚构格式示例，再替换成自己的公开地点：

```text
示例市 | 虚构广场
```

第一批设为 1。类别和范围必须是当前页面真正提供的选项。展开“本机页面标签与窗口设置”，填写唯一窗口、进程名、搜索框标签和列表锚点。筛选菜单可能要先展开，再选择子选项；按实际顺序逐行填写。

首页没有输入框提示文字、但右侧有“搜索”按钮和完整边框时，可选择“首页边框与搜索按钮”；否则使用输入框的实际可见文字定位。坐标从当前窗口推导，不复用其他电脑的像素位置。

**关键词不等于搜索中心。** 先在小程序中核对城市与选定地点，再确定范围。页面没有目标半径时不能直接填一个不存在的选项，也不能把其他定位的“附近”当成目标周边。中心/条件无法确认时，应继续校准而非启动采集。

核对后勾选“我已核对城市、搜索中心、范围和本机点击步骤”，再保存任务。保存会创建新工作区并保留旧记录。此确认只解除启动预检；后续仍要通过界面证据、终页、分页和安全门禁。

## 4. 独立测试 Reqable 上报

点击“获取本机上传地址”。在 Reqable 中选择“调试 → 报告服务器 → 新建报告服务器”，分别添加：

```text
https://*.dianping.com/*
https://*.meituan.com/*
```

两条规则用同一个完整上传 URL，包含 `/report/` 后的随机路径。压缩选 Gzip 或无。子菜单中“报告服务器”和两条规则前应有勾；显示“禁用”表示当前已启用，不要点它。修改已有配置进入“管理规则”。

点击网页“测试上报 · 30秒”，随后在小程序正常产生一次新请求。这个测试不需要模型 Key，不操作微信，不绑定任务，也不保存收到的上报内容。只显示 POST、有效报告、匹配/忽略数量和受控错误码。看到“上报连接已验证”只说明 HTTP/HAR 连接正常，不说明任务、响应字段或分页已通过。

| 现象 | 下一步 |
|---|---|
| POST 为 0 | 检查规则开关、完整 URL，确认有新请求；历史记录不会补传 |
| 地址不匹配 | 重新复制完整上传 URL；它不是网页端口或抓包代理端口 |
| 压缩不支持 | 改为 Gzip 或无 |
| 已连通，但真实运行匹配数据为 0 | 核对当前任务、响应时间窗与平台适配器 |
| 有匹配数据，分页仍不完整 | 检查终页与缺页，不能强制完成 |

抓包保持只面向目标小程序。模型 API、ChatGPT、Codex 与 VPN 网络应与 Reqable 分开；本程序不修改系统代理或 VPN，不安装证书，不重放私有接口。

## 5. 接入模型并执行

在工作台选择服务商和对应协议，填写账户支持的模型、基础地址和 Key。Codex 同类网关使用“Codex / Responses 兼容 API”，可选择推理强度。详细参数见 [多模型指南](model-providers.md)。Key 只在运行内存使用，不写到配置或报告，也不要提交 GitHub。

先点“测试 API 连接”。这一步有一次真实工具调用，可能产生 API 费用。通过后，勾选允许操作小程序，点击“开始 / 继续本批”，保持小程序在前台。网页会显示模型轮次、当前工具和上报计数。

Agent 依次检查环境、规划下一项、执行已校准界面流程、等待终页与完整上报、解析和校验、脱敏导出、保存进度。每项保存后才继续下一项。没有原始证据支持的完成声明不会更新任务状态。

## 6. 检查结果与恢复

任务完成且 HAR 已保存后，在网页显示的结果目录打开 `shops.csv`、`products.csv`，人工核对首项的店名、价格、单位和范围。`result.json`、`compact.json` 与清单供复核。

失焦、验证码、登录、访问限制、缺页或模型失败会停止。修复后点击“重试”，再启动；这会创建新的搜索会话。不要连续重试模型来解决页面标签或抓包配置问题。

首个真实任务与首批通过后，才考虑 5 项批次与定时运行。其他电脑须各自安装、配置账户、校准并验证。

## CLI 使用同一个 Agent

网页显示的配置路径可以交给 CLI；同一时间只运行一个入口：

```powershell
$taskConfig = Read-Host '本地任务配置路径'
./.venv/Scripts/python.exe -B -m groupbuy --config $taskConfig doctor
./.venv/Scripts/python.exe -B -m groupbuy --config $taskConfig plan
./.venv/Scripts/python.exe -B -m groupbuy --config $taskConfig capture-init
./.venv/Scripts/python.exe -B -m groupbuy --config $taskConfig capture-probe --seconds 30
# 按多模型指南配置当前终端的密钥与模型后：
./.venv/Scripts/python.exe -B -m groupbuy --config $taskConfig agent --allow-ui
```

CLI 真实运行前同样需要 D 盘的 `GB_TEMP_DIR`、`TEMP`、`TMP`。安装或启动脚本已经设置这些变量。当前支持范围与实测限制见 [验证状态](validation.md)。
